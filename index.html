1.1프로그램 구조와 출력

자바 코드는 반드시 클래스 안에 있고, 프로그램은 main 메서드부터 실행됩니다. 파일 이름은 public class 이름과 같아야 합니다(Main.java).

public class Main {                        // 클래스 이름 = 파일 이름
    public static void main(String[] args) { // 실행 시작점
        System.out.println("안녕, 자바");     // 출력 후 줄바꿈
        System.out.print("줄바꿈 ");          // 줄바꿈 없음
        System.out.print("없음\n");           // \n 직접 넣기

        String name = "kim";
        int age = 25;
        System.out.println("이름: " + name + ", 나이: " + age);  // + 로 이어붙이기
        System.out.printf("이름: %s, 나이: %d%n", name, age);   // 형식 지정 출력
        System.out.printf("소수 둘째 자리: %.2f%n", 3.14159);    // 3.14
    }
}

1.4형변환

작은 타입 → 큰 타입은 자동, 큰 타입 → 작은 타입은 (타입)을 붙여 직접 바꿉니다. 문자열과 숫자 사이는 메서드로 바꿉니다.

double d = n;                 // 자동: 10.0

char c = 'A';
int code = c;                 // 65 (유니코드 값)
char next = (char) (c + 1);   // 'B'
int digit = '7' - '0';        // 7 (숫자 문자 → 정수)

// 문자열 → 숫자
int x = Integer.parseInt("123");
double y = Double.parseDouble("3.14");
long z = Long.parseLong("10000000000");

// 숫자 → 문자열
String s1 = String.valueOf(123);   // "123"
String s2 = Integer.toString(123); // "123"

1.8메서드

[접근제어자] [static] 반환타입 이름(매개변수) 모양입니다. 돌려줄 값이 없으면 반환 타입은 void입니다.

public class Calculator {

    public int add(int a, int b) {        // 값을 돌려줌
        return a + b;
    }

    public void printSum(int a, int b) {  // 돌려줄 값 없음
        System.out.println(a + b);
    }

    // 오버로딩: 이름이 같아도 매개변수 타입·개수가 다르면 OK
    public double add(double a, double b) {
        return a + b;
    }

    // 가변 인자: 개수 상관없이 받기 (내부에서는 배열)
    public int sumAll(int... nums) {
        int s = 0;
        for (int n : nums) s += n;
        return s;
    }

    // static 메서드: 객체 없이 클래스 이름으로 호출
    public static int square(int x) {
        return x * x;
    }
}

Calculator calc = new Calculator();
calc.add(3, 4);               // 7   (객체.메서드)
calc.sumAll(1, 2, 3, 4);      // 10
Calculator.square(5);         // 25  (클래스.메서드)

값 전달 · 자바는 항상 값을 복사해서 넘깁니다. 기본 타입은 값이 복사돼서 메서드 안에서 바꿔도 밖에 영향이 없고, 객체는 주소가 복사돼서 메서드 안에서 객체 내용을 바꾸면 밖에서도 바뀐 게 보입니다.

2.2Scanner java.util.Scanner · 키보드 입력

import java.util.Scanner;

Scanner sc = new Scanner(System.in);

String word = sc.next();          // 공백 전까지 한 단어
int age = sc.nextInt();           // 정수
double h = sc.nextDouble();       // 실수
sc.nextLine();                    // ← 남은 엔터 비우기 (아래 설명)
String line = sc.nextLine();      // 공백 포함 한 줄 전체

// N개 입력받기 (입력 예: "3" 다음 줄 "10 20 30")
int n = sc.nextInt();
int[] arr = new int[n];
for (int i = 0; i < n; i++) arr[i] = sc.nextInt();

// 숫자가 아닌 입력 거르기
while (!sc.hasNextInt()) {

sc.close();
메서드읽는 것입력 → 결과
nextInt() / nextLong() / nextDouble()숫자 하나42 → 42
next()공백·엔터 전까지 한 단어hong gildong → "hong"
nextLine()엔터 전까지 한 줄 전체hong gildong → "hong gildong"
hasNextInt() / hasNext()다음 입력이 정수인지 / 남았는지입력 검증, 끝까지 읽기

nextInt 다음 nextLine 함정 · nextInt()는 숫자만 가져가고 엔터(\n)를 남겨둡니다. 바로 다음 nextLine()은 그 엔터를 읽고 빈 문자열을 돌려줍니다. 숫자 입력 뒤 한 줄을 받으려면 sc.nextLine();을 한 번 더 호출해 비웁니다.

Spring에서는 · 웹 서버의 입력은 키보드가 아니라 HTTP 요청이라 Scanner를 쓰지 않습니다. 대신 @RequestBody, @PathVariable, @RequestParam으로 받습니다.

2.3BufferedReader 빠른 입력 · 코딩테스트용

import java.io.*;

public interface DiscountPolicy {
    int discount(int price);                      // 구현 없이 선언만

    default boolean isFree(int price) {           // default 메서드: 기본 구현 제공 가능
        return discount(price) >= price;
    }
}

public class FixDiscountPolicy implements DiscountPolicy {
    @Override
    public int discount(int price) { return 1000; }
}

public class RateDiscountPolicy implements DiscountPolicy {
    @Override
    public int discount(int price) { return price / 10; }
}

public class OrderService {
    private final DiscountPolicy policy;          // 구현체가 뭔지 모름

    public OrderService(DiscountPolicy policy) {  // 밖에서 넣어줌
        this.policy = policy;
    }

    public int pay(int price) {
        return price - policy.discount(price);
    }
}

new OrderService(new RateDiscountPolicy()).pay(20000);  // 18000 → 구현만 바뀌고 OrderService 코드는 그대로

// 타입 확인 + 꺼내기 (Java 16+ 패턴 매칭)
if (policy instanceof RateDiscountPolicy rate) {
    // rate 를 RateDiscountPolicy 타입으로 바로 사용
}

3.6Object 메서드 toString · equals · hashCode

public class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) { this.x = x; this.y = y; }

    @Override
    public String toString() {                // println 했을 때 보이는 문자열
        return "Point(" + x + ", " + y + ")";
    }

    @Override
    public boolean equals(Object o) {         // 값이 같으면 같은 객체로 취급
        if (this == o) return true;
        if (!(o instanceof Point p)) return false;
        return x == p.x && y == p.y;
    }

    @Override
    public int hashCode() {                   // equals 를 바꾸면 반드시 함께
        return Objects.hash(x, y);
    }
}

new Point(1, 2).equals(new Point(1, 2));  // true
Set<Point> set = new HashSet<>(List.of(new Point(1, 2), new Point(1, 2)));
set.size();                                // 1 (hashCode 까지 재정의했기 때문)

4.4람다와 메서드 참조 -> · ::

람다는 "이름 없는 함수"입니다. 메서드가 하나뿐인 인터페이스(함수형 인터페이스) 자리에 넣을 수 있습니다.

(a, b) -> {                      // 여러 줄이면 중괄호 + return

    return sum * 2;
}

package com.example.hello.repository;

import com.example.hello.domain.Member;
import org.springframework.stereotype.Repository;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;

@Repository
public class MemoryMemberRepository implements MemberRepository {

    private final Map<Long, Member> store = new ConcurrentHashMap<>();
    private final AtomicLong sequence = new AtomicLong();

    @Override
    public Member save(Member member) {
        member.setId(sequence.incrementAndGet());
        store.put(member.getId(), member);
        return member;
    }

    @Override
    public Optional<Member> findById(Long id) {
        return Optional.ofNullable(store.get(id));
    }

    @Override
    public Optional<Member> findByName(String name) {
        return store.values().stream()
                .filter(m -> m.getName().equals(name))
                .findFirst();
    }

    @Override
    public List<Member> findAll() {
        return new ArrayList<>(store.values());
    }
}

6.2셀프 체크 질문

==와 equals()는 언제 결과가 다른가?

==는 두 변수가 같은 객체(주소)를 가리키는지, equals()는 값이 같은지 봅니다. new String("hi") == "hi"는 false, .equals는 true. 기본 타입(int 등)은 ==로 값 비교가 맞습니다.

기본 타입과 래퍼 클래스(int vs Integer)의 차이는?

int는 값 자체, Integer는 객체입니다. Integer는 null이 될 수 있고 컬렉션·제네릭에 넣을 수 있습니다. 서로 자동 변환(오토박싱)되지만 null을 언박싱하면 NPE가 납니다.

static 메서드와 일반 메서드의 차이는?

static은 클래스에 붙어 객체 없이 클래스.메서드()로 부르고, 객체 필드를 쓸 수 없습니다. 일반 메서드는 객체에 붙어 객체.메서드()로 부르고 그 객체의 필드를 씁니다.

오버로딩과 오버라이딩의 차이는?

오버로딩: 같은 클래스에서 이름은 같고 매개변수가 다른 메서드 여러 개. 오버라이딩: 자식 클래스가 부모 메서드를 같은 모양으로 다시 정의.

인터페이스를 쓰면 무엇이 좋은가?

사용하는 코드가 구현체가 아니라 약속(인터페이스)에만 의존하므로, 구현을 바꿔도(메모리 저장 → DB 저장) 사용하는 코드는 수정하지 않아도 됩니다. 테스트에서 가짜 구현을 넣기도 쉽습니다.

추상 클래스와 인터페이스는 언제 각각 쓰나?

공통 코드(필드, 구현된 메서드)를 물려주고 싶으면 추상 클래스, 역할만 정하고 구현은 자유롭게 바꾸고 싶으면 인터페이스. 클래스는 하나만 상속하지만 인터페이스는 여러 개 구현할 수 있습니다.

equals를 재정의하면 왜 hashCode도 재정의해야 하나?

HashMap/HashSet은 먼저 hashCode로 칸을 찾고 그다음 equals로 비교합니다. equals가 같아도 hashCode가 다르면 다른 칸에 들어가서 중복으로 저장됩니다.

Checked 예외와 Unchecked 예외의 차이는? 서버 커스텀 예외는 보통 어느 쪽?

Checked(IOException 등)는 try-catch나 throws가 강제되고, Unchecked(RuntimeException 하위)는 강제되지 않습니다. 서버 커스텀 예외는 보통 RuntimeException을 상속하고, 전역 핸들러(@RestControllerAdvice)에서 한 번에 처리합니다.

Optional.orElse와 orElseGet의 차이는?

orElse(x)는 값이 있어도 x를 항상 미리 계산합니다. orElseGet(() -> x)는 값이 없을 때만 실행합니다. x를 만드는 비용이 크거나 DB 조회라면 orElseGet을 씁니다.

Member::getName은 무슨 뜻인가?

메서드 참조입니다. m -> m.getName()을 줄여 쓴 것으로, "Member를 받아서 getName()을 호출한 결과를 돌려주는 함수"입니다.

Entity 목록을 DTO 목록으로 바꾸는 한 줄은?

members.stream().map(MemberResponse::from).toList()

왜 필드에 private final을 붙이고 생성자로 받는가?

final이면 한 번 주입된 의존성이 바뀌지 않음이 보장되고, 생성자로 받으면 객체가 만들어질 때 반드시 채워집니다. 테스트에서 new Service(가짜Repository)로 직접 넣을 수도 있습니다.

DI를 Spring 없이 한 문장으로 설명하면?

객체가 필요한 의존 객체를 스스로 new 하지 않고, 바깥에서 생성자로 넣어 주는 것입니다.

Service 빈에 요청별 값을 필드로 저장하면 왜 안 되나?

Spring 빈은 기본적으로 싱글톤이라 모든 요청 스레드가 같은 객체를 공유합니다. 필드에 요청별 값을 저장하면 동시에 들어온 다른 요청이 덮어써서 데이터가 섞입니다.

record는 DTO에 쓰는데 왜 Entity에는 안 쓰나?

record는 불변(필드 변경 불가)이고 기본 생성자가 없습니다. JPA는 기본 생성자로 객체를 만들고 필드 값을 바꿔 가며 관리해야 해서 record와 맞지 않습니다.
